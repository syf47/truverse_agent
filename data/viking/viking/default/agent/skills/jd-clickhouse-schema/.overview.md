### When to use
This skill is applicable when you need to construct SQL queries for JD e-commerce data, conduct analysis on commodity information, user comments, and user Q&A data based on ClickHouse storage.

### How to use
1. Confirm the target shop ID first to replace the `{shopId}` placeholder in the table names of the three core tables (commodity table `jd_{shopId}_wares`, comment table `jd_{shopId}_comments`, Q&A table `jd_{shopId}_qa`).
2. Associate tables following the rules: commodity and comment tables are associated via `wares.wareId = comments.sku_id` (Int64 type direct matching); commodity and Q&A tables are associated via `toString(wares.wareId) = qa.item_id` (type conversion required).
3. Query required fields from corresponding tables according to analysis demands, refer to built-in common query templates for single-dimension analysis (such as in-stock commodity information, comment score distribution, negative comment content, popular Q&A) or multi-table joint analysis (such as brand dimension commodity and comment comprehensive statistics).

### Why to use
It solves the problem of lack of clear table structure definition, association rule, and query standard when querying and analyzing JD e-commerce commodity, comment, and Q&A data, avoids errors caused by unfamiliarity with table field rules, storage logic and partition strategies, and improves the efficiency of data query and analysis.

### Key features
1. Clear storage logic: All three tables use MergeTree engine, partitioned by month based on corresponding time fields, with clear sorting keys to optimize query efficiency; the comment table has a 365-day TTL for automatic data cleaning, and the Q&A table stores one answer per row with redundant question information.
2. Complete field coverage: The commodity table covers core attributes such as basic commodity information, price inventory, status, details, logistics and extension attributes; the comment table covers comment content, score, image, interaction and user information; the Q&A table covers complete question and answer information.
3. Built-in standard query modes: Provides common query templates for multiple scenarios such as commodity information query, comment analysis, Q&A query, brand dimension comprehensive analysis, covering most common analysis demands.
4. Key constraint prompts: Includes core precautions such as `wareStatus=8` for in-stock commodities, `has_image=1 AND imiage_status=1` for reviewed晒单 images, and requirement of grouping by `question_id` when querying Q&A questions, to avoid query errors.
